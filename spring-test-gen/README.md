# 仕様書からSpringテスト

API の仕様書を先に渡して、Spring Boot の Web API テスト（JUnit 5）を Claude に作ってもらうツールです。
ブラウザだけで動きます。

## 使い方

1. [`../dist/spring-test-gen.html`](../dist/spring-test-gen.html) を開きます（ダブルクリックでOK）。
2. 仕様書を貼りつけます。Markdown・OpenAPI（YAML / JSON）・ふつうの文章のどれでも読めます。
   コントローラや DTO のコードがあれば「いまあるコードも渡す」に貼ると、クラス名をそれに合わせます。
3. Spring Boot のバージョン、テストの方式、パッケージを選びます。
4. **テスト観点を作る** → 観点の表を確かめます。いらない観点はチェックを外し、タイトルは書きかえられます。
5. **テストコードを作る** → コントローラごとにテストクラスができます。
6. 観点の漏れと、自動チェックの「要修正」があれば **足りない分を作る / 直す** を押します。
7. コピーするか、zip で保存して、プロジェクトの `src/test/java` に入れ、`./gradlew test` で確かめます。

## Claude へのつなぎ方

| つなぎ方 | いるもの | 説明 |
| --- | --- | --- |
| claude.ai | claude.ai のアカウント | claude.ai で公開したページを開いたときだけ選べます。API キーはいりません |
| API キー | Anthropic の API キー | ブラウザから公式 SDK（`@anthropic-ai/sdk`）で直接呼びます。使った分の料金と、キャッシュで節約できた額を表示します |
| コピーして使う | なし | プロンプトをコピーしてチャットに貼り、答えを貼り戻すと、同じチェックができます |

## テストの方式

| 方式 | 中身 |
| --- | --- |
| `@WebMvcTest` + `MockMvc` | コントローラだけを起動。サービスなどは `@MockitoBean`（3.0〜3.3 は `@MockBean`）でモック |
| `@WebMvcTest` + `MockMvcTester` | 上と同じで、AssertJ 形式（Spring Boot 3.4 から） |
| `@SpringBootTest` + `MockMvc` | アプリ全体を起動する結合テスト。`@Transactional` で後片付け |

Spring Boot は 4.x / 3.4〜3.5 / 3.0〜3.3 から選べます。バージョンによって `@WebMvcTest` のパッケージや
`@MockBean` / `@MockitoBean` が違うので、プロンプトでも自動チェックでも、そこを合わせます。

## よい結果を出すための工夫

- **2段階にする。** いきなりコードを作らず、まず観点の表（JSON）を作ります。人が確かめてから、コードを作ります。
  観点には「仕様書のどこが根拠か」と「仕様か推測か」が付き、仕様書のあいまいな点は「確認したい点」として一覧になります。
- **観点IDで漏れを数える。** テストには `@DisplayName("[C001] …")` を付けさせ、全部の観点がテストになったかを数えます。
- **仕様書だけを正しい答えにする。** 実装のコードを渡しても、期待値は仕様書から取るように指示しています。
- **壊れやすい書き方を避ける。** リクエストの JSON はテキストブロックで書かせ、`ObjectMapper` を使わせません
  （Spring Boot 4 で Jackson 3 に変わったため）。
- **コンパイル前のチェック。** 古いパッケージ、削除された `@MockBean`、JUnit 4 の import、`{ }` の数、
  何も確かめていないテスト、`Thread.sleep` などを見つけます。

## API キーで使うときの料金の工夫

- `system`（書き方の決まり）と仕様書は、どの呼び出しでも同じ文字列・同じ順番で先頭に置き、仕様書の最後にキャッシュの区切りを置いています。
- 1つ目のテストクラスを作り終えてから残りを並べて作るので、2つ目以降は仕様書の部分がキャッシュから読まれます（入力の料金が約1/10）。
- 観点づくりは構造化出力（JSON Schema）で、形の崩れた答えが返らないようにしています。
- Opus / Sonnet では、安全のための判定で断られたときに、サーバー側でおすすめのモデルにつなぎ直す設定（`fallbacks: "default"`）を付けています。

## ファイル

```
index.html            画面
src/prompts.js        プロンプト（書き方の決まり・観点づくり・コードづくり・直し）と観点の JSON Schema
src/core.js           答えを読む・コードを取り出す・漏れを数える・自動チェック・zip・料金の目安
src/engines.js        Claude の呼び出し口（claude.ai / API キー）
src/samples.js        例の仕様書
src/app.js            画面の動き
vendor/anthropic-sdk.js  公式 SDK をブラウザ用にまとめたもの（npm run vendor で作りなおす）
test/core.test.js     テスト
```
