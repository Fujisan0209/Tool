仕様書からSpringテスト

API の仕様書を先に渡して、Spring Boot の Web API テストを Claude に作ってもらうツールです。まず「テスト観点」の表を作って確かめ、そのあと観点どおりの JUnit 5 テストコードを作ります。できたコードは、観点の漏れと、バージョンちがいのまちがいを自動でチェックします。

コントローラ・DTO・サービス・例外クラスのコードを貼ると、クラス名やメソッド名をそれに合わせます。期待値は仕様書のほうを優先します。

Claude へのつなぎ方

仕様書は、選んだつなぎ方の Claude にだけ送ります。

  1. テスト観点仕様書から洗い出す
  2. テストコード観点1件 = テスト1つ
  3. チェック漏れ・まちがいを確認
  1. 下のボタンでプロンプトをコピーして、Claude（claude.ai など）のチャットに貼りつけます。
  2. 返ってきた答えを、まるごと下の欄に貼りつけて「答えを読みこむ」を押します。
  3. コードを取り出して、観点の漏れとまちがいをチェックします。

先に観点を見る

いきなりコードを作らず、まず「何を確かめるか」の表を作ります。不要な観点はチェックを外し、タイトルは書きかえられます。仕様書のあいまいな点も一覧にします。

観点IDで漏れを数える

テストには @DisplayName("[C001] …") の形で観点IDを付けさせ、全部の観点がテストになったかを数えます。足りない分は、ボタン1つで書き足してもらえます。

バージョンのちがいを見張る

Spring Boot 4 で削除された @MockBean、移った @WebMvcTest のパッケージ、JUnit 4 の import などを、コンパイル前に見つけます。

API キーで使うときは、キーはこのブラウザから Anthropic の API に直接送るだけで、ほかには送りません。共有のパソコンでは「覚える」を付けないでください。仕様書が同じなら、2つ目以降のテストクラスは仕様書の部分がキャッシュから読まれ、入力の料金が約1/10になります。
